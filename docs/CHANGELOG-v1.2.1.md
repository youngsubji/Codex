# 업무 일정 대시보드 v1.2.1

수정일: 2026-11-02 (한국 시간)

## 원인 및 수정

- 기존 `projectDates()`가 프로젝트와 하위 업무 전체의 최소 시작일 / 최대 종료일을 사용했습니다. 제공된 JSON에서 TAG3 갭/외관검사(납품전)의 종료일은 2026-11-02지만, 불량/양품 샘플테스트의 종료일은 2026-11-05여서 프로젝트 막대까지 11/05로 연장되었습니다. 첨부된 두 스크린샷과도 일치합니다.
- 프로젝트 막대와 툴팁은 프로젝트 자체의 시작일 / 종료일을 사용하도록 수정했습니다. 하위 업무는 자체 날짜로 표시되므로 해당 하위 업무 막대는 계속 11/05까지 표시됩니다.
- 프로젝트 및 하위 업무 등록/수정 화면에서 ESC를 누르면 취소 버튼과 동일한 `closeForm()`을 호출합니다. 저장이나 동기화는 발생하지 않습니다. 캘린더 선택 중간 상태도 취소 시 초기화합니다.
- 연동 설정 창에서는 ESC가 기존 닫기 함수를 호출합니다. 한글 조합 중 ESC와 키 자동 반복은 무시합니다.
- HTML 제목, 버전 표시, 저장 데이터의 앱 버전은 1.2.1로 갱신했습니다.

## 호환성 및 원본

- 이전 대화에서 제공된 HTML은 파일명에 v1.1.1이 있으나 실제 내부 버전은 v1.2.0입니다. 수정은 이 첨부 HTML을 기준으로 했습니다.
- 저장 키, 연동 설정 키, Apps Script 주소, JSON 필드 및 프로젝트/하위 업무 ID 관계를 유지했습니다.
- 별도의 Apps Script 첨부파일은 이전 대화 도구에서 제공되지 않았습니다. HTML에 내장된 전체 Apps Script의 doGet/doPost 및 시트 열 매핑을 검토했으며 변경하지 않았습니다. 내장 스크립트의 응답 버전 1.2.0도 기존 그대로입니다. 이 수정에 Apps Script 재배포는 필요하지 않습니다.
- `original/`에 원본 HTML과 JSON을 보존했습니다. 실제 Google Sheets 데이터는 수정하지 않았습니다.

## 검증

Chrome 헤드리스 브라우저에서 17개 검증 통과. 결과는 `tests/results.json`, 재실행은 `python tests/run_tests.py`입니다. 테스트는 별도의 임시 브라우저 프로필에서 수행하며 네트워크 응답을 대체합니다.

- 실제 백업의 프로젝트 3개 / 하위 업무 14개 로드 및 JSON 복원
- 프로젝트 11/02, 하위 업무 11/05의 막대 폭과 툴팁, 조회 기간 밖 프로젝트 숨김
- 프로젝트/하위 업무 등록 및 편집 ESC 취소, 데이터·로컬 저장·통신 미변경
- 재개방 시 기존 값 복원, 한글 조합 중 ESC 무시, 설정 창 닫기
- 종료일 편집 저장 및 즉시 재표시, 기존 동기화 POST 필드와 날짜 보존
- 원본 대비 내장 Apps Script·저장 키·연동 주소 동일성 확인

실제 운영 Google Sheets와의 통신 및 Netlify 배포는 수행하지 않았습니다. GitHub에 올리지 않았습니다.

## 사용

`project_schedule_dashboard_v1.2.1.html`을 Chrome 또는 Edge에서 여세요. 기존과 동일한 연동 주소가 포함되어 있으므로 일반 실행 시 기존과 같이 시트 데이터를 읽고, 등록/수정/삭제하면 시트로 저장할 수 있습니다.

기존 HTML과 새 로컬 파일은 브라우저의 파일 저장소가 다를 수 있습니다. 필요한 경우 기존 JSON 백업을 복원할 수 있으나, 기존 동작대로 복원 내용도 연결된 시트에 동기화됩니다.

운영 사이트에 반영하려면 기존 배포 방식을 사용해 새 HTML로 교체해야 합니다. 이번 결과물은 로컬 수정 파일이며 운영 사이트는 변경하지 않았습니다.
